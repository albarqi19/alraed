# زاحف «الرائد» — أداةٌ تجرّب الموقع كما يجرّبه العميل

هذه أداةٌ **تفتح متصفّحاً حقيقياً**، وتدخل إلى النظام بكلّ دور، وتزور كلَّ صفحة،
وتضغط الأزرار الآمنة، ثم تعطيك تقريراً بما هو متعطّل.

وهي الطبقة الثالثة في فحص المنصّة، والوحيدة التي ترى ما يراه المستخدم:

| الأداة | ماذا تفحص | ماذا تفوّت |
| --- | --- | --- |
| `php artisan audit:api-contract` | تطابق نداءات الفرونت مع مسارات الباك | لا تفتح متصفّحاً |
| `php artisan audit:smoke-endpoints` | هل ترتدّ نقاط الـAPI بخطأ ٥٠٠ | لا تعرف شيئاً عن الواجهة |
| **هذا الزاحف** | الصفحة نفسها: هل ظهرت؟ هل انهارت؟ هل نجح زرّها؟ | — |

ولماذا الطبقة الثالثة هي الأهمّ؟ لأن أوجع الأعطال وقعت فيها بالضبط: صفحة الاستيراد
كانت بيضاء بعد «جاري المعالجة» والباك يردّ ٢٠٠ سليماً؛ وملفّ الطالب ردّ ٤٢٢ والباك
سليمٌ والفرونت يبني مدىً مقلوباً. **الباك لا يكشف هذه. الزاحف يكشفها.**

---

## ⚠ قاعدةٌ لا تُكسر: الزحف على قاعدة الاختبار لا الإنتاج

الزاحف **يضغط أزراراً**. وضغطُ زرٍّ على الإنتاج ليس فحصاً — بل حادثة.

ولذلك فيه أربعة حواجز:

1. **الافتراضات كلُّها محلّية** — لا يوجد أيّ عنوان إنتاجٍ في إعداداته.
2. **حارسٌ قبل التشغيل** — أيّ عنوانٍ غير `localhost` يوقف الزاحف بخطأ واضح،
   ما لم تضبط `E2E_ALLOW_REMOTE=1` بيدك وأنت تعرف ما تفعل.
3. **بناءٌ خاصّ** — `npm run e2e:build` يقرأ `.env.e2e` فيوجّه عنوان الـAPI ومقبس
   Reverb إلى المحلّي، ويُطفئ Firebase. فلا قناةَ خارجيةً مفتوحةً أصلاً.
4. **درعٌ داخل المتصفّح** — حتى لو أخطأ أحدٌ في البناء، يُجهض الزاحف كلَّ نداءِ
   بياناتٍ إلى مضيفٍ غير محلّيٍّ ويكتب في التقرير أنّ الحزمة مبنيّةٌ خطأً.

> **انتبه:** عنوان الـAPI في الفرونت **يُخبَز في الحزمة وقت البناء**. لا يكفي أن
> تضبط `E2E_API_BASE_URL`؛ يجب أن تبني الفرونت بـ `npm run e2e:build`
> (انظر خطوة ٣ أدناه). ملفّ `.env` الحاليّ في المستودع يشير إلى الإنتاج.
>
> والدرع يحمي نداءات `xhr/fetch` وحدها — أمّا **WebSocket** فلا يمرّ عليه. ولهذا
> يجب أن يأتي القطعُ من البناء لا من الزاحف: مقبس Reverb وقاعدة Firebase الحيّة
> كانا سيتّصلان بالإنتاج بلا أن يشعر أحد.

## التهيئة — مرّةً واحدة

### ١) نزّل المتصفّح

```bash
npm run e2e:install
```

ينزّل Chromium وحده (لا الثلاثة — التنزيل ثقيل ولا داعي له).

### ٢) ابذر قاعدة الاختبار وشغّل الباك عليها

من مجلّد الباك `c:/laragon/www/attendance-system`:

```bash
php artisan test:setup-database

# البذرة تطبع JSON نقيّاً على stdout — احفظه حيث يقرؤه الزاحف
DB_DATABASE=attendance_system_test php artisan e2e:seed --quiet-seeders \
  > "فرونت جديد/e2e/generated/seed-payload.json"

DB_DATABASE=attendance_system_test php artisan serve --host=127.0.0.1 --port=8010
```

الأمر `e2e:seed` يرفض العملَ على قاعدةٍ لا ينتهي اسمُها بـ `_test` — فلا يمكن أن
يكتب على قاعدة الإنتاج بالخطأ.

ومن هذه الحمولة يقرأ الزاحف **كلَّ شيء**: بيانات الدخول للأدوار الخمسة، ومعرّفات
المسارات ذات البارامترات (`/admin/forms/:formId`…). فلا تكتب معرّفاً بيدك: هي
تتغيّر مع كلّ إعادة بناءٍ للقاعدة.

### ٣) ابنِ الفرونت «هدفَ زحف» وقدّمه

```bash
# من مجلّد الفرونت
npm run e2e:build    # vite build --mode e2e
npm run e2e:serve    # vite preview على 127.0.0.1:3000
```

الوضع `--mode e2e` يقرأ ملفّ `.env.e2e` في جذر الفرونت، وهو يوجّه **كلّ** قناةٍ
خارجيةٍ إلى المحلّي: عنوان الـ API، ومقبس Reverb، ويُطفئ Firebase. وهذا ليس
تزيّناً:

> عنوان الـ API **يُخبَز في الحزمة وقت البناء**. وملفّ `.env` الأصليّ يشير إلى
> `api.brqq.site` أي **الإنتاج**. فلو بنيتَ بـ `npm run build` العاديّ ثم زحفتَ
> على `localhost`، لضربت صفحاتُك خادمَ الإنتاج وأنت تحسبها محلّية.

اترك نافذة المعاينة مفتوحة.

### ٤) اكتب عناوين التشغيل

انسخ `e2e/.env.example` إلى `e2e/.env`:

```ini
E2E_BASE_URL=http://127.0.0.1:3000
E2E_API_BASE_URL=http://127.0.0.1:8010/api
E2E_SEED_FILE=./e2e/generated/seed-payload.json
```

ولا حاجة لكتابة بيانات الدخول: تُقرأ من حمولة البذرة. (ولو أردت تجاوزها فمتغيّرات
`E2E_ADMIN_NATIONAL_ID` وأخواتها ما تزال تعمل وتتقدّم على الحمولة.)

ملفّ `e2e/.env` مستبعَدٌ من git — لن تُرفع كلمات مرورٍ إلى المستودع.

#### ⚠ عن اختيار المنفذ — درسٌ دفعنا ثمنه

اختر منفذاً حرّاً، وتحقّق: `netstat -ano | findstr :3000`. وفي أوّل تشغيلٍ كامل
لهذه العدّة ضاعت **أربع دقائق** من الزحف لأن منفذ المعاينة كان محجوزاً على IPv6
(`[::1]`) بخادم تطويرٍ لمشروعٍ آخر، بينما حجزت معاينتُنا IPv4 وحدها — و`localhost`
على ويندوز يُحلّ إلى IPv6 أوّلاً. فزحف الزاحف على **تطبيقٍ آخر**، وردّ ذلك
التطبيق بصفحة «٤٠٤» على كلّ عنوان، وصفحةُ ٤٠٤ فيها نصٌّ وأزرار… فعُدّت «سليمة».
وخرج تقريرٌ يقول «١٣٧ صفحةً سليمة» ولم تُفحص صفحةٌ واحدةٌ من نظامنا.

لذلك أمران:

1. اكتب `127.0.0.1` صراحةً في `E2E_BASE_URL`، لا `localhost`.
2. حارسٌ في `global-setup` يفتح الصفحة قبل أيّ اختبار ويتحقّق أنّها تطبيقُنا،
   وإلا رفض التشغيل كلَّه. تقريرٌ لا يوجد خيرٌ من تقريرٍ يطمئنك كذباً.

## التشغيل

```bash
npm run e2e          # الزحف الكامل
npm run e2e:report   # افتح التقرير في المتصفّح
```

وبينهما أمرٌ خفيفٌ مفيد:

```bash
npm run e2e:routes   # اعرض ما سيُفحص — في ثانية، بلا فتح متصفّح
```

### تشغيلٌ جزئيّ

```bash
npx playwright test --project=الإدارة        # دورٌ واحد
npx playwright test -g "/admin/import"       # صفحةٌ واحدة
npx playwright test --headed                 # شاهد المتصفّح وهو يعمل
```

## كيف تقرأ التقرير

بعد التشغيل تجد في `e2e/report/`:

| الملفّ | لمن |
| --- | --- |
| **`تقرير-الزحف.html`** | لك. افتحه بالنقر — كلُّ شيءٍ بداخله واللقطات مضمّنة. |
| `تقرير-الزحف.md` | لمن يريد نصّاً يلصقه في محادثة أو مهمّة. |
| `crawl-results.json` | للأدوات والبرمجة. |
| `screenshots/` | لقطةٌ لكلّ صفحةٍ فيها ملاحظة. |

### الدرجات الثلاث

| الدرجة | معناها | ماذا تفعل |
| --- | --- | --- |
| 🔴 **عطل** | الصفحة لا تعمل: بيضاء، أو انهارت، أو الخادم ردّ ٥٠٠، أو ٤٢٢ عند مجرّد الفتح | أصلحه قبل فتح النظام للمدارس |
| 🟡 **مشبوه** | نداءٌ ردّ ٤٠١/٤٠٣/٤٠٤، أو خطأٌ في وحدة التحكّم | انظر: قد يكون نقصاً في بيانات البذرة، وقد يكون عطلاً |
| ⚪ **متوقَّع** | رفضٌ صحيح (مسارُ دورٍ آخر مثلاً) | لا شيء |

**لماذا ٤٢٢ عطلٌ لا مجرّد شبهة؟** لأن ٤٢٢ تعني «بياناتك غير صالحة». وصفحةُ عرضٍ
لا يُفترض أن ترسل بياناتٍ غير صالحة لمجرّد أنّك فتحتها. هذا بالضبط ما وقع في ملفّ
الطالب.

### قسم «صفحاتٌ لم تُفحص ولماذا» — لا تتجاهله

صفحةٌ لم تُفحص **ليست صفحةً سليمة**. القسم موجودٌ عمداً كي لا يبدو التقرير أشملَ
ممّا هو. أكثر الأسباب شيوعاً: مسارٌ فيه معرّف (`/admin/forms/:formId`) ولا نملك
معرّفاً حقيقياً — والحلّ أن تضبط المتغيّر المناسب في `e2e/.env`.

### قسم «أدوارٌ تعذّر الدخول بها» — الأخطر

إن ظهر هذا القسم فمعناه أنّ **عشرات الصفحات لم تُفحص إطلاقاً**. التقرير حينها لا
يقول عنها شيئاً — لا سلامةً ولا عطلاً. تحقّق من بيانات الدخول في `e2e/.env`.

## ماذا يُرصد في كلّ صفحة؟

1. **شاشة بيضاء** — لا نكتفي بطول نصّ الصفحة: صفحةٌ فيها الهيدر والقائمة الجانبية
   وحدهما ليست بيضاء تقنياً لكنّها بيضاء في عين المستخدم. فالقياس يقتصر على منطقة
   المحتوى. ونميّز «فارغة لأنّها بلا بيانات» (رسالةٌ مشروعة) عن «فارغة لأنّها انهارت».
2. **خطأ console** — بعد ترشيح الضجيج المعروف.
3. **انهيار React** — استثناءٌ غير ملتقَط، أو ظهور نصّ حدود الخطأ.
4. **نداءٌ فاشل** — كلُّ ٤xx/٥xx، مصنَّفةً بالدرجات الثلاث أعلاه.

وزيادةً: **مهلةٌ منتهية** (صفحةٌ لم تُحمَّل خلال ٢٥ ثانية) تُسجَّل عطلاً لا تُتخطّى
صامتة؛ و**قذفٌ إلى صفحة الدخول** يُسجَّل عطلاً لا يُحسب محتوىً سليماً.

### وما **لا** يُفحص — بحدودٍ معلنة

* **عاملُ الخدمة (PWA)** محجوبٌ عمداً (`serviceWorkers: 'block'`). التطبيق يُنادي
  `location.reload()` حين يتغيّر المتحكّم، فيُعاد تحميلُ الصفحة في منتصف القياس
  وتُلتقط اللقطةُ بيضاء ويُعلَن عطلٌ لا وجود له. وأخطر: العاملُ قد يخدم نسخةً
  مخبَّأةً قديمة فيُفحص بناءٌ ليس بناءَنا. فالعملُ بلا إنترنت وإشعارُ التحديث
  خارج نطاق هذا الفحص.
* **Firebase** مُطفأٌ في بناء `--mode e2e` (النداء الآليّ الحيّ). البديل كان أن
  يفتح المتصفّح قاعدةَ Firebase **الإنتاجية** أثناء الفحص.
* **مقبس Reverb** موجَّهٌ للمحلّي، فالتحديثُ اللحظيّ في المحادثات لا يُختبر.
* **بوّابة واتساب** غير مشغّلةٍ محلّياً؛ نقاطُ حالة النسخة تردّ ٥٠٠ وهي مصنّفةٌ
  «متوقَّع» في `noise-filters.ts`.

## الأزرار — ولماذا يُمنع أكثرُها

بعد استقرار الصفحة يضغط الزاحف الأزرار **الآمنة** ويعيد الرصد.

**الافتراض هو المنع.** لا يُضغط زرٌّ إلا إن ثبت أنّه آمن. ويُمنع صراحةً كلُّ ما فيه:
حذف · إزالة · مسح · أرشفة · إلغاء · تعطيل · إرسال · نشر · اعتماد · رفض · تصدير ·
طباعة · حفظ · تسجيل الخروج — وكلُّ زرٍّ من نوع `submit` داخل نموذج، وكلُّ زرٍّ بلا
نصٍّ ولا تسمية (نيّتُه مجهولة).

سترى في التقرير عدد «الأزرار المُنعت عمداً»، وهو عادةً أكبر من عدد المجرَّبة. هذا
مقصود: ثمنُ تفويت زرٍّ آمنٍ زهيدٌ أمام ثمن إرسال رسالةِ واتسابٍ إلى وليّ أمرٍ حقيقيّ.

> يفوز المنعُ على السماح دائماً: زرُّ تبويبٍ مكتوبٌ عليه «تصدير» يُمنع رغم أنّه
> تبويب. القاعدة تُبقى على تحفّظها عمداً.

## الصيانة

### أضفتُ صفحةً جديدة — هل أعدّل شيئاً؟

**لا.** قائمة الصفحات تُستخرج آلياً من `src/app/router/app-router.tsx` عند كلّ
تشغيل. أضف مسارك هناك وسيُفحص تلقائياً في أوّل تشغيلٍ بعده.

تحقّق بـ:

```bash
npm run e2e:routes
```

### صفحتي فيها معرّف في المسار ولا تُفحص

أوّلاً تأكّد أنّ حمولة البذرة حاضرة (`E2E_SEED_FILE`): منها تأتي المعرّفات
الحقيقية، وبها هبط عددُ المتخطّى من ١٤ مساراً إلى صفر.

ولو أردت قيمةً بيدك، اضبطها في `e2e/.env` — وهي تتقدّم على الحمولة:

```ini
E2E_FORM_ID=3
```

ولو كان بارامتراً جديداً كلّياً، أضفه في `e2e/config/seed-payload.mjs`
(دالّة `routeParams`)، وأضف مفتاحه إلى `e2e/.env.example`.

**والبارامتر `:id` حالةٌ خاصّة**: ليس شيئاً واحداً في كلّ المسارات — هو إحالةٌ في
`/admin/referrals/:id`، وحالةٌ طلابيةٌ في `/guidance/cases/:id`، وخطّةٌ علاجيةٌ في
`/guidance/treatment-plans/:id`. ولذلك تُخرج البذرة `route_params`: تعييناً خاصّاً
بكلّ مسارٍ على حدة، يتقدّم على التعيين العامّ. قيمةٌ عامّةٌ واحدةٌ كانت ستصيب
واحداً وتُخطئ الباقين، فيردّ الباك ٤٠٤ ويُقرأ عطلاً وهو ليس عطلاً.

### التقرير ممتلئٌ بخطأٍ لا يهمّني

وسّع قائمة الترشيح في **`e2e/config/noise-filters.ts`**. أضف نصّاً أو تعبيراً نمطياً
إلى المصفوفة المناسبة، **واكتب تعليقاً يقول لماذا هو ضجيج** — وإلا صارت القائمة بعد
سنةٍ ستاراً يخفي أعطالاً حقيقية.

```ts
export const consoleNoisePatterns: Array<string | RegExp> = [
  // ...
  /رسالتي المزعجة/,   // السبب: مكتبة كذا تطبعها دائماً ولا أثر لها على المستخدم
]
```

### زرٌّ آمنٌ يُمنع / زرٌّ خطرٌ يُضغط

عدّل **`e2e/config/button-policy.ts`**. وللمطوّر طريقان أوضح: ضع
`data-e2e="safe"` على زرٍّ تريد تجربته، أو `data-e2e="unsafe"` على زرٍّ يجب ألّا
يُلمس أبداً.

### الزحف بطيء

```bash
E2E_PROBE_BUTTONS=false npm run e2e   # زحف تحميلٍ فقط، أسرع بكثير
E2E_WORKERS=4 npm run e2e             # لا ترفعه فوق ٤: الباك المحلّي واحد
```

## ملاحظاتٌ للمطوّر

- عدّة الزحف **خارج** `npm run build` عمداً: `tsc -b` يبني `src` وحدها. خطأُ نوعٍ
  في أداة فحصٍ لا يجوز أن يمنع نشر المنتج. لفحص أنواع العدّة:
  `npm run e2e:typecheck`.
- التبعية الوحيدة المضافة: `@playwright/test`.
- حالات المصادقة تُحفظ في `e2e/.auth/` وتحوي توكناتٍ حيّة — المجلّد مستبعَدٌ من git.
- الجلسة تُحقن في `localStorage` بمفتاحين معاً: `auth_token` (يقرؤه معترض axios)
  و`auth-storage` (مخزن zustand، ومنه يعرف حارسُ المسار أنّك مسجَّل). كتابةُ أحدهما
  دون الآخر تُنتج جلسةً نصفَ حيّة.
- التقرير الـHTML يضمّن اللقطات كـ`data:` URI بصيغة JPEG بجودة ٧٢٪ — كي يبقى
  ملفاً واحداً يُفتح بالنقر دون أن يتضخّم إلى عشرات الميغابايت.
