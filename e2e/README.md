# عدّة «الرائد» للفحص بالمتصفّح — زحفٌ ورحلات

هنا أداتان **تفتحان متصفّحاً حقيقياً** وتدخلان إلى النظام بكلّ دور:

* **الزاحف** يزور كلَّ صفحة ويضغط الأزرار الآمنة، فيجيب: **هل تُفتح الصفحة؟**
* **الرحلات** تفعل الميزة كما يفعلها المستخدم ثمّ تتحقّق من أثرها، فتجيب:
  **هل تعمل الميزة؟**

وهما الطبقة الثالثة في فحص المنصّة، والوحيدة التي ترى ما يراه المستخدم:

| الأداة | ماذا تفحص | ماذا تفوّت |
| --- | --- | --- |
| `php artisan audit:api-contract` | تطابق نداءات الفرونت مع مسارات الباك | لا تفتح متصفّحاً |
| `php artisan audit:smoke-endpoints` | هل ترتدّ نقاط الـAPI بخطأ ٥٠٠ | لا تعرف شيئاً عن الواجهة |
| **الزاحف** (`npm run e2e`) | الصفحة نفسها: هل ظهرت؟ هل انهارت؟ هل نجح زرّها؟ | لا يحفظ ولا يرسل — فلا يعرف إن كانت الميزة تعمل |
| **الرحلات** (`npm run e2e:journeys`) | الميزة من طرفها إلى طرفها: كُتبت؟ استقرّت في القاعدة؟ ظهرت في مكانٍ آخر؟ | ليست شاملة: رحلةٌ لكلّ ميزةٍ تُكتب بيدٍ |

ولماذا الطبقة الثالثة هي الأهمّ؟ لأن أوجع الأعطال وقعت فيها بالضبط: صفحة الاستيراد
كانت بيضاء بعد «جاري المعالجة» والباك يردّ ٢٠٠ سليماً؛ وملفّ الطالب ردّ ٤٢٢ والباك
سليمٌ والفرونت يبني مدىً مقلوباً. **الباك لا يكشف هذه. الزاحف يكشفها.**

وأعطالٌ أخرى لا يكشفها الزاحفُ نفسُه: زرٌّ يُضغط فلا يحفظ، وتقريرٌ يعرض صفراً
والقاعدة مملوءة، ونموذجٌ يُنشَر فلا يبلغ وليَّ أمرٍ واحداً. **هذه تكشفها الرحلات
وحدها** — لأنّ الزاحف يقرأ ولا يكتب.

---

## ⚠ قاعدةٌ لا تُكسر: الزحف على قاعدة الاختبار لا الإنتاج

الزاحف **يضغط أزراراً**. وضغطُ زرٍّ على الإنتاج ليس فحصاً — بل حادثة.

ولذلك فيه أربعة حواجز:

1. **الافتراضات كلُّها محلّية** — لا يوجد أيّ عنوان إنتاجٍ في إعداداته.
2. **حارسٌ قبل التشغيل** — أيّ عنوانٍ غير `localhost` يوقف الزاحف بخطأ واضح،
   ما لم تضبط `E2E_ALLOW_REMOTE=1` بيدك وأنت تعرف ما تفعل.
3. **بناءٌ خاصّ** — `npm run e2e:build` يقرأ `.env.e2e` فيوجّه عنوان الـAPI ومقبس
   Reverb إلى المحلّي، ويُطفئ Firebase. فلا قناةَ خارجيةً مفتوحةً أصلاً.
4. **درعٌ داخل المتصفّح** — حتى لو أخطأ أحدٌ في البناء، يُجهض الزاحف كلَّ نداءِ
   بياناتٍ إلى مضيفٍ غير محلّيٍّ ويكتب في التقرير أنّ الحزمة مبنيّةٌ خطأً.

> **انتبه:** عنوان الـAPI في الفرونت **يُخبَز في الحزمة وقت البناء**. لا يكفي أن
> تضبط `E2E_API_BASE_URL`؛ يجب أن تبني الفرونت بـ `npm run e2e:build`
> (انظر خطوة ٣ أدناه). ملفّ `.env` الحاليّ في المستودع يشير إلى الإنتاج.
>
> والدرع يحمي نداءات `xhr/fetch` وحدها — أمّا **WebSocket** فلا يمرّ عليه. ولهذا
> يجب أن يأتي القطعُ من البناء لا من الزاحف: مقبس Reverb وقاعدة Firebase الحيّة
> كانا سيتّصلان بالإنتاج بلا أن يشعر أحد.

## التهيئة — مرّةً واحدة

### ١) نزّل المتصفّح

```bash
npm run e2e:install
```

ينزّل Chromium وحده (لا الثلاثة — التنزيل ثقيل ولا داعي له).

### ٢) ابذر قاعدة الاختبار وشغّل الباك عليها

من مجلّد الباك `c:/laragon/www/attendance-system`:

```bash
php artisan test:setup-database

# البذرة تطبع JSON نقيّاً على stdout — احفظه حيث يقرؤه الزاحف
DB_DATABASE=attendance_system_test php artisan e2e:seed --quiet-seeders \
  > "فرونت جديد/e2e/generated/seed-payload.json"

DB_DATABASE=attendance_system_test php artisan serve --host=127.0.0.1 --port=8010
```

الأمر `e2e:seed` يرفض العملَ على قاعدةٍ لا ينتهي اسمُها بـ `_test` — فلا يمكن أن
يكتب على قاعدة الإنتاج بالخطأ.

ومن هذه الحمولة يقرأ الزاحف **كلَّ شيء**: بيانات الدخول للأدوار الخمسة، ومعرّفات
المسارات ذات البارامترات (`/admin/forms/:formId`…). فلا تكتب معرّفاً بيدك: هي
تتغيّر مع كلّ إعادة بناءٍ للقاعدة.

### ٣) ابنِ الفرونت «هدفَ زحف» وقدّمه

```bash
# من مجلّد الفرونت
npm run e2e:build    # vite build --mode e2e
npm run e2e:serve    # vite preview على 127.0.0.1:3000
```

الوضع `--mode e2e` يقرأ ملفّ `.env.e2e` في جذر الفرونت، وهو يوجّه **كلّ** قناةٍ
خارجيةٍ إلى المحلّي: عنوان الـ API، ومقبس Reverb، ويُطفئ Firebase. وهذا ليس
تزيّناً:

> عنوان الـ API **يُخبَز في الحزمة وقت البناء**. وملفّ `.env` الأصليّ يشير إلى
> `api.brqq.site` أي **الإنتاج**. فلو بنيتَ بـ `npm run build` العاديّ ثم زحفتَ
> على `localhost`، لضربت صفحاتُك خادمَ الإنتاج وأنت تحسبها محلّية.

اترك نافذة المعاينة مفتوحة.

### ٤) اكتب عناوين التشغيل

انسخ `e2e/.env.example` إلى `e2e/.env`:

```ini
E2E_BASE_URL=http://127.0.0.1:3000
E2E_API_BASE_URL=http://127.0.0.1:8010/api
E2E_SEED_FILE=./e2e/generated/seed-payload.json
```

ولا حاجة لكتابة بيانات الدخول: تُقرأ من حمولة البذرة. (ولو أردت تجاوزها فمتغيّرات
`E2E_ADMIN_NATIONAL_ID` وأخواتها ما تزال تعمل وتتقدّم على الحمولة.)

ملفّ `e2e/.env` مستبعَدٌ من git — لن تُرفع كلمات مرورٍ إلى المستودع.

#### ⚠ عن اختيار المنفذ — درسٌ دفعنا ثمنه

اختر منفذاً حرّاً، وتحقّق: `netstat -ano | findstr :3000`. وفي أوّل تشغيلٍ كامل
لهذه العدّة ضاعت **أربع دقائق** من الزحف لأن منفذ المعاينة كان محجوزاً على IPv6
(`[::1]`) بخادم تطويرٍ لمشروعٍ آخر، بينما حجزت معاينتُنا IPv4 وحدها — و`localhost`
على ويندوز يُحلّ إلى IPv6 أوّلاً. فزحف الزاحف على **تطبيقٍ آخر**، وردّ ذلك
التطبيق بصفحة «٤٠٤» على كلّ عنوان، وصفحةُ ٤٠٤ فيها نصٌّ وأزرار… فعُدّت «سليمة».
وخرج تقريرٌ يقول «١٣٧ صفحةً سليمة» ولم تُفحص صفحةٌ واحدةٌ من نظامنا.

لذلك أمران:

1. اكتب `127.0.0.1` صراحةً في `E2E_BASE_URL`، لا `localhost`.
2. حارسٌ في `global-setup` يفتح الصفحة قبل أيّ اختبار ويتحقّق أنّها تطبيقُنا،
   وإلا رفض التشغيل كلَّه. تقريرٌ لا يوجد خيرٌ من تقريرٍ يطمئنك كذباً.

## التشغيل

```bash
npm run e2e:all                  # الزحف كاملاً بأمرٍ واحد: يهيّئ ويبذر ويبني ويشغّل وينظّف
npm run e2e:all -- --journeys    # وبعده الرحلات على الخادمين نفسِهما
npm run e2e:journeys -- --seed --build --serve   # الرحلات وحدها، من الصفر
npm run e2e:report               # افتح تقرير الزحف في المتصفّح
```

ولو كان الباك والواجهة يعملان عندك أصلاً:

```bash
npm run e2e          # الزحف وحده (playwright test)
npm run e2e:journeys # الرحلات وحدها — تتحقّق من الخادمين وتقول أمرَيهما إن كانا مطفأين
```

وأمرٌ خفيفٌ مفيد:

```bash
npm run e2e:routes   # اعرض ما سيُفحص — في ثانية، بلا فتح متصفّح
```

### تشغيلٌ جزئيّ

```bash
npx playwright test --project=الإدارة        # دورٌ واحد
npx playwright test -g "/admin/import"       # صفحةٌ واحدة
npx playwright test --headed                 # شاهد المتصفّح وهو يعمل

npm run e2e:journeys -- --serve e2e/journeys/03-attendance.spec.ts   # رحلةٌ واحدة
```

> **لا تنتقِ الرحلةَ بـ`--grep "الرحلة ٣"`**: الغلافُ يقسم النصَّ عند المسافة
> فيصير `--grep الرحلة` وتردّ Playwright «No tests found». مرّر مسار الملفّ.

## الزحف والرحلات — متى تُشغّل أيَّهما؟

|  | الزحف | الرحلات |
| --- | --- | --- |
| **السؤال** | هل تُفتح الصفحة؟ | هل تعمل الميزة؟ |
| **ما يفعله** | يزور ١٣٩ صفحةً بخمسة أدوار، ويضغط الأزرار الآمنة | ستّةُ ملفّاتٍ (ثماني رحلات) تُنشئ وتحفظ وترصد وتنشر وتتراجع |
| **الكتابة** | ممنوعة: حفظ · إرسال · حذف · اعتماد كلُّها محجوبة | **هي الغرض** — ثمّ يُقاس أثرُها |
| **التغطية** | شاملةٌ آلياً (تُستخرج من الراوتر) | مقصودةٌ باليد: رحلةٌ لكلّ ميزةٍ حرجة |
| **الزمن** | دقائق (٣ عمّال) | ~٥ دقائق (عاملٌ واحدٌ إلزاماً) |
| **متى** | بعد أيّ تغييرٍ في الواجهة أو المسارات؛ وقبل كلّ نشر | قبل النشر؛ وبعد أيّ تغييرٍ يمسّ الحفظ أو التقارير أو النماذج أو النقاط |
| **التقرير** | `e2e/report/تقرير-الزحف.html` | `e2e/report/journeys/تقرير-الرحلات.html` |

ولا يجتمعان في تشغيلٍ واحد: الرحلاتُ تقيس «كان ٧ فصار ٨»، وهذا القياس يفسد إن
كتب عاملٌ آخرُ صفّاً في أثنائه. فالإعدادُ يفرض للرحلات `workers: 1` و`retries: 0`
(إعادةُ رحلةٍ كتبت نصفَ ما تكتب تُنشئ الصفَّ مرّتين). و`--journeys` في
`e2e:all` يُشغّلهما **بالتتابع** على الخادمين نفسِهما، لا معاً.

### ⚠ لا أثرَ خارجيّاً — شرطٌ لا يُساوَم عليه

الرحلات تكتب بياناتٍ حقيقية، وبعضُ ما تكتبه يُطلق أثراً **يغادر الجهاز**: رسالةَ
واتسابٍ لوليّ أمر، أو إشعاراً، أو بثّاً حيّاً. ورسالةٌ واحدةٌ تصل إلى وليّ أمرٍ
حقيقيّ من اختبارٍ آليّ عطلٌ جسيم. فالعدّة لا تفترض السلامة بل **تقيسها**:

1. **حارسُ بيئةٍ قبل أوّل كتابة** (`_support/safety.ts`) يرفض التشغيل عند: قاعدةٍ
   لا تنتهي بـ`_test` · `QUEUE_CONNECTION=sync` (فكلُّ `dispatch` يُنفَّذ داخل
   الطلب) · بوّابة واتساب غير محلّية · بثٍّ حيٍّ غير محلّي.
2. **حارسُ هُويّة الباك العامل**: يسأل الخادمَ الذي يخدم المنفذ «مَن حاملُ هذا
   التوكن؟» ثمّ يبحث عن الصفّ نفسِه في القاعدة التي نقيس عليها. فخادمٌ متروكٌ من
   تشغيلٍ سابقٍ على **قاعدة التطوير** يُمسَك هنا — ولولاه لكتبنا في قاعدةٍ
   وقِسنا في أخرى فخرج التقرير «صفرٌ فصفر» طمأنينةً كاذبة.
3. **عدّادُ الأثر** يُقرأ قبل كلّ رحلةٍ وبعدها: `whatsapp_messages` و`jobs`
   و`failed_jobs`. أيُّ زيادةٍ في الرسائل أو في المهامّ **الفاشلة** (وفشلُ مهمّةٍ
   يعني أنّ عاملاً حيٌّ يلتقط) تُسقط الرحلة فوراً.
4. **إعلانُ ما يصطفّ**: مهمّةٌ تدخل الطابور بلا `journey.expectQueued` تُسقط
   الرحلة. الأثرُ غيرُ المُعلَن هو ما نصطاده.
5. **درعُ المتصفّح** يُجهض أيّ نداءٍ إلى مضيفٍ غير محلّي، وفحصٌ قبل التشغيل يمسح
   `dist/assets/*.js` بحثاً عن عنوان API خارجيّ ويرفض البدء.

والرقمان — قبل وبعد — يُطبعان في أوّل جدولٍ من تقرير الرحلات. لا وعدَ بأنّ شيئاً
لم يخرج، بل قياس.

## كيف تُضاف رحلةٌ جديدة

الرحلةُ ملفٌّ واحدٌ في `e2e/journeys/` باسم `NN-اسم-بالإنجليزية.spec.ts`. والرقمُ
يرتّب التنفيذ، فاجعل ما يعتمد على بياناتٍ ثابتةٍ أوّلاً.

```ts
import { test, expect } from './_support/journey'
import { apiAs, sessionFile, NO_SESSION, type ApiBridge } from './_support/api-bridge'
import { countRows, firstRow } from './_support/php-bridge'
import { uniqueStudentName } from './_support/unique'

test.describe('الرحلة ٧ — كذا', () => {
  test.use({ storageState: sessionFile('teacher') })   // أو NO_SESSION للزائر

  test('عنوانٌ يصف ما تُثبته الرحلة', async ({ page, journey }) => {
    journey.about({ role: 'المعلم', purpose: 'يُثبت أنّ …' })

    const api = await apiAs('teacher')
    try {
      const before = await journey.measure('سجلّات الحضور', () => countRows('attendances', { school_id: 9012 }))

      await journey.step('فتحُ الصفحة', async () => { /* … */ })
      await journey.step('الفعلُ من الواجهة', async () => { /* … */ })

      await journey.confirm(before, () => countRows('attendances', { school_id: 9012 }), 1,
        'فعلٌ واحدٌ = سجلٌّ واحد.')
    } finally {
      await api.dispose()
    }
  })
})
```

**واجهة `journey`:**

| النداء | ما يفعله |
| --- | --- |
| `about({role, purpose})` | يُعرّف الرحلة في رأس بطاقتها في التقرير. **استدعِه أوّلاً**. |
| `await journey.step(عنوان, دالّة)` | يسجّل الخطوة، ويلتقط لقطةً عند فشلها، ويُرجع ما تُرجعه الدالّة |
| `await journey.measure(وصف, قراءة)` | الرقمُ **قبل** |
| `await journey.confirm(قياس, قراءة, فرق, لماذا)` | الرقمُ **بعد**، ويؤكّد الفرق: «كان ٩ فصار ١٠ والمتوقَّع +١» |
| `journey.expectQueued(طابور, عدد, لماذا)` | **إلزاميّ** لكلّ رحلةٍ تُطلق مهمّة |
| `journey.created(وصف)` | يسجّل ما تركته على القاعدة كي يعرف المالك ما يحذف |
| `journey.note(نصّ)` | ملاحظةٌ حرّةٌ في التقرير |
| `journey.markSkipped(سبب)` + `test.skip(true, سبب)` | تخطٍّ **مُعلَن**: يظهر ⏭ لا ✘ |

**والجسور:**

* `php-bridge` — `countRows(جدول, شرط)` · `firstRow(جدول, شرط)` · `phpJson(تعبير, قيم)`.
  مرّر القيم في `bindings` واقرأها بـ`$__b['key']`؛ لا تلصق نصّاً عربياً في
  التعبير. وكلُّ نداءٍ ≈ ثانيةٌ ونصف، **فاجمع قراءاتك في نداءٍ واحد**.
* `api-bridge` — `apiAs('admin'|'teacher'|'super-admin'|'guardian')` يُعطيك جسراً
  **بالتوكن نفسِه** الذي يحمله المتصفّح (لا دخولٌ جديد: `auth/login` عليه حدُّ
  عشرِ محاولاتٍ في الدقيقة لكلّ عنوان). و`bridge.raw()` حين يكون رمزُ الحالة هو
  المُتحقَّق منه. و`await api.dispose()` في `finally` دائماً.
* `session.ts` — `installSession(page, token, user)` لتبديل الدور داخل الصفحة نفسِها.
* `unique.ts` — أسماءُ الجولة: كلُّ ما تُنشئه يحمل «تجريبي» ووسماً فيُعرف ويُحذف.

### خمسُ قواعدَ تُبقي الرحلة صادقة

1. **تحقّق من وجهين معاً**: ما يراه المستخدم (الواجهة) وما استقرّ في القاعدة.
   حوارٌ يُغلق ليس دليلاً على حفظ — انتظر الاستجابة وأكّد رمزها (`waitForResponse`).
2. **قِس فرقاً لا رقماً مطلقاً**: «صار ٥» قد يكون ٥ قبل الفعل. والفرقُ وحده يكشف
   الحفظَ المكرَّر (زرٌّ يُرسل الطلب مرّتين).
3. **احسب المتوقَّع بنفسك من القاعدة**، لا من التقرير نفسِه: استعلامٌ ينسى مدرسةً
   يُنتج مجموعاً متّسقاً مع صفوفه تماماً — وكاذباً تماماً.
4. **اختر هدفك من القاعدة لا برقمٍ مثبَّت**: المعرّفاتُ تتغيّر مع كلّ بذرة.
5. **نظّف بعدك**، وهيّئ شرطَك إن لزم. الرحلةُ التي لا تُعاد مرّتين متتاليتين
   ماتت بعد أوّل تشغيل. (انظر «استعارة الفصل» في `03-attendance.spec.ts`: ترفع
   سجلّاتِ اليومِ المبذورة ثمّ تُعيدها بعينها.)

### مصائدُ وقعنا فيها

* `auth/me` يردّ `{data:{user:{…}}}` لا `{data:{…}}`. افحص شكل الاستجابة قبل أن تفترضه.
* `getByRole('button', {name:'إضافة طالب'})` يلتقط «إضافة طالب جديد» أيضاً — استعمل `exact: true`.
* الجداول مُرقَّمة (٥٠ صفّاً): قِس الصفوف ما دامت الصفحة غير ممتلئة، أو ابحث
  بالاسم المميّز وأكّد `toHaveCount(1)`.
* لا تثبّت رقماً محسوباً (كنسبة تقدّم) — عُدَّ الأشياء نفسَها بدلاً منه.
* الباك المحلّي `artisan serve` **متسلسل**: انتظر وصولَ خيارِ القائمة قبل
  `selectOption`، ومرّر مهلةً صريحة.
* `WsModal` بلا `role="dialog"` — التقطه بـ`.ws-modal`.

## كيف تقرأ التقرير

بعد التشغيل تجد في `e2e/report/`:

| الملفّ | لمن |
| --- | --- |
| **`تقرير-الزحف.html`** | لك. افتحه بالنقر — كلُّ شيءٍ بداخله واللقطات مضمّنة. |
| `تقرير-الزحف.md` | لمن يريد نصّاً يلصقه في محادثة أو مهمّة. |
| `crawl-results.json` | للأدوات والبرمجة. |
| `screenshots/` | لقطةٌ لكلّ صفحةٍ فيها ملاحظة. |
| **`journeys/تقرير-الرحلات.html`** | تقرير الرحلات — بطاقةٌ لكلّ رحلة بخطواتها وقياساتها. |
| `journeys/journey-results.json` | نتائج الرحلات للأدوات. |

### وفي تقرير الرحلات: اقرأ الجدول الأوّل قبل كلّ شيء

أوّلُ جدولٍ فيه هو **«الأثر الخارجيّ: هل خرج شيء؟»** — رقمان لكلّ رحلة: رسائل
الواتساب المسجَّلة قبلها وبعدها. وأيُّ رقمٍ غير صفرٍ في عمود الفرق بلوكرٌ يعلو
كلَّ عطلٍ آخرَ في التقرير.

ثمّ لكلّ رحلةٍ بطاقة: ما تُثبته · بأيّ دور · خطواتُها ✓/✘ · قياساتُها
(«كان ٩ فصار ١٠ والمتوقَّع +١») · ما أنشأته وتركته على القاعدة. والرحلةُ
المتخطّاة تظهر ⏭ بسببٍ مكتوب — لا تُقرأ نجاحاً ولا فشلاً.

### الدرجات الثلاث

| الدرجة | معناها | ماذا تفعل |
| --- | --- | --- |
| 🔴 **عطل** | الصفحة لا تعمل: بيضاء، أو انهارت، أو الخادم ردّ ٥٠٠، أو ٤٢٢ عند مجرّد الفتح | أصلحه قبل فتح النظام للمدارس |
| 🟡 **مشبوه** | نداءٌ ردّ ٤٠١/٤٠٣/٤٠٤، أو خطأٌ في وحدة التحكّم | انظر: قد يكون نقصاً في بيانات البذرة، وقد يكون عطلاً |
| ⚪ **متوقَّع** | رفضٌ صحيح (مسارُ دورٍ آخر مثلاً) | لا شيء |

**لماذا ٤٢٢ عطلٌ لا مجرّد شبهة؟** لأن ٤٢٢ تعني «بياناتك غير صالحة». وصفحةُ عرضٍ
لا يُفترض أن ترسل بياناتٍ غير صالحة لمجرّد أنّك فتحتها. هذا بالضبط ما وقع في ملفّ
الطالب.

### قسم «صفحاتٌ لم تُفحص ولماذا» — لا تتجاهله

صفحةٌ لم تُفحص **ليست صفحةً سليمة**. القسم موجودٌ عمداً كي لا يبدو التقرير أشملَ
ممّا هو. أكثر الأسباب شيوعاً: مسارٌ فيه معرّف (`/admin/forms/:formId`) ولا نملك
معرّفاً حقيقياً — والحلّ أن تضبط المتغيّر المناسب في `e2e/.env`.

### قسم «أدوارٌ تعذّر الدخول بها» — الأخطر

إن ظهر هذا القسم فمعناه أنّ **عشرات الصفحات لم تُفحص إطلاقاً**. التقرير حينها لا
يقول عنها شيئاً — لا سلامةً ولا عطلاً. تحقّق من بيانات الدخول في `e2e/.env`.

---

## ماذا يُرصد في كلّ صفحة؟

1. **شاشة بيضاء** — لا نكتفي بطول نصّ الصفحة: صفحةٌ فيها الهيدر والقائمة الجانبية
   وحدهما ليست بيضاء تقنياً لكنّها بيضاء في عين المستخدم. فالقياس يقتصر على منطقة
   المحتوى. ونميّز «فارغة لأنّها بلا بيانات» (رسالةٌ مشروعة) عن «فارغة لأنّها انهارت».
2. **خطأ console** — بعد ترشيح الضجيج المعروف.
3. **انهيار React** — استثناءٌ غير ملتقَط، أو ظهور نصّ حدود الخطأ.
4. **نداءٌ فاشل** — كلُّ ٤xx/٥xx، مصنَّفةً بالدرجات الثلاث أعلاه.

وزيادةً: **مهلةٌ منتهية** (صفحةٌ لم تُحمَّل خلال ٢٥ ثانية) تُسجَّل عطلاً لا تُتخطّى
صامتة؛ و**قذفٌ إلى صفحة الدخول** يُسجَّل عطلاً لا يُحسب محتوىً سليماً.

### وما **لا** يُفحص — بحدودٍ معلنة

* **عاملُ الخدمة (PWA)** محجوبٌ عمداً (`serviceWorkers: 'block'`). التطبيق يُنادي
  `location.reload()` حين يتغيّر المتحكّم، فيُعاد تحميلُ الصفحة في منتصف القياس
  وتُلتقط اللقطةُ بيضاء ويُعلَن عطلٌ لا وجود له. وأخطر: العاملُ قد يخدم نسخةً
  مخبَّأةً قديمة فيُفحص بناءٌ ليس بناءَنا. فالعملُ بلا إنترنت وإشعارُ التحديث
  خارج نطاق هذا الفحص.
* **Firebase** مُطفأٌ في بناء `--mode e2e` (النداء الآليّ الحيّ). البديل كان أن
  يفتح المتصفّح قاعدةَ Firebase **الإنتاجية** أثناء الفحص.
* **مقبس Reverb** موجَّهٌ للمحلّي، فالتحديثُ اللحظيّ في المحادثات لا يُختبر.
* **بوّابة واتساب** غير مشغّلةٍ محلّياً؛ نقاطُ حالة النسخة تردّ ٥٠٠ وهي مصنّفةٌ
  «متوقَّع» في `noise-filters.ts`.

## الأزرار — ولماذا يُمنع أكثرُها

بعد استقرار الصفحة يضغط الزاحف الأزرار **الآمنة** ويعيد الرصد.

**الافتراض هو المنع.** لا يُضغط زرٌّ إلا إن ثبت أنّه آمن. ويُمنع صراحةً كلُّ ما فيه:
حذف · إزالة · مسح · أرشفة · إلغاء · تعطيل · إرسال · نشر · اعتماد · رفض · تصدير ·
طباعة · حفظ · تسجيل الخروج — وكلُّ زرٍّ من نوع `submit` داخل نموذج، وكلُّ زرٍّ بلا
نصٍّ ولا تسمية (نيّتُه مجهولة).

سترى في التقرير عدد «الأزرار المُنعت عمداً»، وهو عادةً أكبر من عدد المجرَّبة. هذا
مقصود: ثمنُ تفويت زرٍّ آمنٍ زهيدٌ أمام ثمن إرسال رسالةِ واتسابٍ إلى وليّ أمرٍ حقيقيّ.

> يفوز المنعُ على السماح دائماً: زرُّ تبويبٍ مكتوبٌ عليه «تصدير» يُمنع رغم أنّه
> تبويب. القاعدة تُبقى على تحفّظها عمداً.

## الصيانة

### أضفتُ صفحةً جديدة — هل أعدّل شيئاً؟

**لا.** قائمة الصفحات تُستخرج آلياً من `src/app/router/app-router.tsx` عند كلّ
تشغيل. أضف مسارك هناك وسيُفحص تلقائياً في أوّل تشغيلٍ بعده.

تحقّق بـ:

```bash
npm run e2e:routes
```

### صفحتي فيها معرّف في المسار ولا تُفحص

أوّلاً تأكّد أنّ حمولة البذرة حاضرة (`E2E_SEED_FILE`): منها تأتي المعرّفات
الحقيقية، وبها هبط عددُ المتخطّى من ١٤ مساراً إلى صفر.

ولو أردت قيمةً بيدك، اضبطها في `e2e/.env` — وهي تتقدّم على الحمولة:

```ini
E2E_FORM_ID=3
```

ولو كان بارامتراً جديداً كلّياً، أضفه في `e2e/config/seed-payload.mjs`
(دالّة `routeParams`)، وأضف مفتاحه إلى `e2e/.env.example`.

**والبارامتر `:id` حالةٌ خاصّة**: ليس شيئاً واحداً في كلّ المسارات — هو إحالةٌ في
`/admin/referrals/:id`، وحالةٌ طلابيةٌ في `/guidance/cases/:id`، وخطّةٌ علاجيةٌ في
`/guidance/treatment-plans/:id`. ولذلك تُخرج البذرة `route_params`: تعييناً خاصّاً
بكلّ مسارٍ على حدة، يتقدّم على التعيين العامّ. قيمةٌ عامّةٌ واحدةٌ كانت ستصيب
واحداً وتُخطئ الباقين، فيردّ الباك ٤٠٤ ويُقرأ عطلاً وهو ليس عطلاً.

### التقرير ممتلئٌ بخطأٍ لا يهمّني

وسّع قائمة الترشيح في **`e2e/config/noise-filters.ts`**. أضف نصّاً أو تعبيراً نمطياً
إلى المصفوفة المناسبة، **واكتب تعليقاً يقول لماذا هو ضجيج** — وإلا صارت القائمة بعد
سنةٍ ستاراً يخفي أعطالاً حقيقية.

```ts
export const consoleNoisePatterns: Array<string | RegExp> = [
  // ...
  /رسالتي المزعجة/,   // السبب: مكتبة كذا تطبعها دائماً ولا أثر لها على المستخدم
]
```

### زرٌّ آمنٌ يُمنع / زرٌّ خطرٌ يُضغط

عدّل **`e2e/config/button-policy.ts`**. وللمطوّر طريقان أوضح: ضع
`data-e2e="safe"` على زرٍّ تريد تجربته، أو `data-e2e="unsafe"` على زرٍّ يجب ألّا
يُلمس أبداً.

### الزحف بطيء

```bash
E2E_PROBE_BUTTONS=false npm run e2e   # زحف تحميلٍ فقط، أسرع بكثير
E2E_WORKERS=4 npm run e2e             # لا ترفعه فوق ٤: الباك المحلّي واحد
```

### رحلةٌ حمراء — أهي عطلُ اختبارٍ أم عطلُ تطبيق؟

هذا السؤال هو كلُّ قيمة الطبقة، والجواب في بطاقة الرحلة بالتقرير: **الخطوةُ**
التي سقطت، والرسالةُ فيها الرقمُ المتوقَّع والرقمُ الواقع.

* الرسالةُ تقول «القاعدة تقول ٣ والشاشة تعرض ٠» ← **عطلُ تطبيق**. سجّله ولا
  تُطفئ الرحلة. رحلةٌ حمراءُ صادقة خيرٌ من خضراءَ كاذبة.
* الرسالةُ تقول «لم أجد الزرّ» أو «انتهت المهلة» ← **عطلُ عدّة** غالباً: محدِّدٌ
  تغيّر مع الواجهة، أو مهلةٌ ضاقت على باكٍ متسلسل. أصلح الرحلة.
* الرسالةُ تقول «كان ٩ فصار ١١ والمتوقَّع +١» ← **حفظٌ مكرَّر**، وهو عطلُ تطبيقٍ
  من أخطر ما تكشفه هذه الطبقة.

### رحلةٌ تتخطّى نفسها (⏭)

التخطّي **مُعلَنٌ دائماً** وسببُه مكتوب: حدُّ محاولاتٍ بلغناه، أو إعدادُ مدرسةٍ
يجعل الكتابةَ خطرة (`send_absence_sms` مفعَّل)، أو بيانات بذرةٍ ناقصة. وهو ليس
نجاحاً: رحلةٌ تتخطّى نفسها لم تُثبت شيئاً.

فإن تخطّت رحلةٌ نفسَها في **كلّ** تشغيل فذاك عطلُ عدّةٍ لا حالةٌ عابرة. (وقع
هذا: كانت رحلةُ الحضور تتخطّى نفسَها على كلّ قاعدةٍ بُذرت للتوّ، لأنّ البذرة
تكتب حضورَ **اليوم** لفصولها كلِّها فلا يبقى فصلٌ نظيفٌ يُرصد فيه. والعلاجُ في
الرحلة نفسِها: تستعير سجلّاتِ اليوم ثمّ تُعيدها.)

### الرحلات تكتب — فأين ما كتبته؟

في بطاقة كلّ رحلةٍ سطرُ «ما أُنشئ وتُرك». والقاعدةُ العامّة أنّ كلَّ رحلةٍ
تنظّف بعدها كي تُعاد مرّتين متتاليتين، إلّا رحلتَي التسجيل وإضافة الطالب: تتركان
أثرَهما عمداً (مدرسةٌ تجريبية وطالبٌ تجريبيّ) لأنّ الحذف نفسَه ليس ما تختبرانه.
وحذفُها آمن:

```sql
-- على attendance_system_test وحدها
DELETE FROM students WHERE name LIKE 'طالب تجريبي%';
DELETE FROM schools  WHERE name LIKE 'مدرسة تجريبية%';
```

### كلُّ الرحلات سقطت برسالة «جلسةٌ محفوظةٌ بلا توكن»

هذه الرسالة **لا تعني عطلاً في المصادقة**، بل أنّ تهيئة المصادقة لم تحصل على
توكن فكتبت حالةَ دورٍ فارغة. والسببُ الشائع أنّ الباك كان مشغولاً: `artisan
serve` متسلسل، ومهلةُ نداء الدخول عشرون ثانية، فيكفي أن يسبقك زحفٌ ثقيل أو
وكيلٌ آخر على الجهاز نفسِه لتنتهي المهلة.

وقع هذا في أوّل تشغيلٍ يجمع الزحفَ والرحلات: نجح الزحف، ثمّ انتهت مهلةُ دخول
`admin` و`teacher`، فسقطت سبعُ رحلات. ولذلك صار المشغّلان ينتظران **هدوء**
الباك — ثلاثَ استجاباتٍ سريعةٍ متتالية — لا مجرّد استجابته، قبل أن يبدآ.

فإن رأيتها اليوم فراجع `e2e/.auth/roles-status.json`: فيه سببُ فشل كلّ دور
مكتوباً. وامسح محدِّدَ المعدّل إن كان الردّ ٤٢٩ (`auth/login` عليه عشرُ محاولاتٍ
في الدقيقة لكلّ عنوان، وكلُّ تشغيلٍ يستهلك أربعاً):

```bash
DB_DATABASE=attendance_system_test php artisan cache:clear
```

### منفذٌ مشغول أو خادمٌ متروك

`php artisan serve` يحجز المنفذ بحفيده (`php -S`)، وقد ينجو الحفيدُ من التنظيف.
والخطرُ ليس الإزعاج: التشغيلُ التالي يموت خادمُه الجديد صامتاً ويستجيب **القديم**
— وقاعدتُه مجهولة، و`.env` الباك يشير إلى قاعدة **التطوير**. ولذلك:

* `run-journeys.mjs` و`run-all.mjs` يحرّران المنفذ بالقتل عمّا يستمع عليه (لا
  بالمعرّف وحده)، ويرفضان `--serve` على منفذٍ مشغولٍ سلفاً.
* وحارسُ الهُويّة في `_support/safety.ts` يمسك ما يفلت: يسأل الباكَ العامل عن
  حاملِ التوكن ويبحث عنه في القاعدة التي نقيس عليها.

وللفحص اليدويّ: `netstat -ano | findstr :8010` ثمّ `taskkill /PID <رقم> /T /F`.

## ملاحظاتٌ للمطوّر

- عدّة الزحف **خارج** `npm run build` عمداً: `tsc -b` يبني `src` وحدها. خطأُ نوعٍ
  في أداة فحصٍ لا يجوز أن يمنع نشر المنتج. لفحص أنواع العدّة:
  `npm run e2e:typecheck`.
- التبعية الوحيدة المضافة: `@playwright/test`.
- حالات المصادقة تُحفظ في `e2e/.auth/` وتحوي توكناتٍ حيّة — المجلّد مستبعَدٌ من git.
- الجلسة تُحقن في `localStorage` بمفتاحين معاً: `auth_token` (يقرؤه معترض axios)
  و`auth-storage` (مخزن zustand، ومنه يعرف حارسُ المسار أنّك مسجَّل). كتابةُ أحدهما
  دون الآخر تُنتج جلسةً نصفَ حيّة.
- التقرير الـHTML يضمّن اللقطات كـ`data:` URI بصيغة JPEG بجودة ٧٢٪ — كي يبقى
  ملفاً واحداً يُفتح بالنقر دون أن يتضخّم إلى عشرات الميغابايت.
