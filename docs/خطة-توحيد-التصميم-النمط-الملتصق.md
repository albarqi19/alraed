# خطة توحيد التصميم — «النمط الملتصق» (Workspace Design System)

> **الحالة (2026-07-16):** المراحل 0+1 ✅، الدفعات 1+2+3 ✅ كاملة، ومن دفعة 7: جداول المعلمين + الانتظار + الإشراف ✅، ومن دفعة 8: ملف المعلم ✅. إضافات خارج الخطة: تحسين القشرة (طيّ القائمة الجانبية لعمود أيقونات + ترويسة ثابتة + بطاقة مستخدم سفلية + تاريخ هجري بالهيدر) ✅، وإزالة الشريط الجانبي الملوّن من كل الصفحات (قرار المالك) ✅. **التالي: دفعة 4 — الطلاب.**
> ملاحظة مؤجلة: صفحة الانتظار فيها ملاحظات تصميمية سيعود لها المالك.
> **المبدأ الحاكم:** ثيم واحد نظيف من tokens، لا تمرير إلا في الأشياء التي فيها تمرير، كثافة برنامج حاسوبي، ولا يُكتب لون صلب في أي صفحة بعد اليوم.

## 2) الطريقة المثلى للبداية (التوصية)

### المرحلة 1 — طبقة مكونات React (قبل أي ترحيل جماعي) ⭐
نسخ الـ markup يدوياً في 60 صفحة = صيانة مستحيلة. نبني مرة واحدة مكونات خفيفة في `src/shared/workspace/`:

```
WsPage, WsHeader (title/badge/actions/facts), WsFact,
WsToolbar, WsField (label+input/select),
WsLayout, WsMain, WsSideCol (الطي + localStorage مدمجان),
WsBlock (head/tools/fill), WsTable (thead لاصق + صف محدد),
WsChip, WsBtn, WsAlert, WsEmpty, WsSpinner, WsModal, WsProgress
```

- مكونات **عرض فقط** (thin wrappers فوق كلاسات `ws-*`) — بلا منطق أعمال، بلا state إلا طيّ العمود.
- بعدها تُعاد كتابة صفحة الحضور بها (تنظيف المرجع نفسه) — فتصير أول صفحة «موثّقة بالكود».
- **مدة متوقعة:** جلسة واحدة. هذا الاستثمار يجعل كل صفحة لاحقة أسرع 3-4 مرات.

### المرحلة 2 فصاعداً — ترحيل بالدفعات (وصفة واحدة لكل دفعة)
كل دفعة = صفحات متشابهة البنية → تُبنى بنفس الوصفة → **معاينة واعتماد** → commit مستقل → الدفعة التالية. لا ننتقل لدفعة قبل اعتماد سابقتها.

## 3) الوصفات الخمس (Archetypes)

| الوصفة | البنية | متى تدخل `WORKSPACE_ROUTES`؟ |
|---|---|---|
| **A — سجل وتفاصيل** | ترويسة + فلاتر + جدول وسط + عمود تفاصيل قابل للطي | ✅ دائماً |
| **B — قائمة كبيرة** | ترويسة + فلاتر + جدول يملأ الشاشة (التفاصيل درج/مودال) | ✅ دائماً |
| **C — لوحة بلوكات** | ترويسة + شبكة بلوكات ملتصقة (إحصاء/ملفات شخصية) | ✅ غالباً |
| **D — شبكة زمنية** | ترويسة + شبكة جدول أسبوعي/حصص تملأ الشاشة | ✅ دائماً |
| **E — إعدادات ونماذج** | نفس الـ tokens والمكونات لكن **صفحة تتمرر طبيعياً** | ❌ لا تدخل |

> قاعدة الوصفة E هي تطبيق مبدأ «لا تمرير إلا في الأشياء التي فيها تمرير» بالعكس: النماذج الطويلة طبيعتها التمرير — نوحّد شكلها لا سلوكها.

## 5) قواعد إلزامية لكل صفحة تُرحَّل (Checklist)

1. **Tokens فقط**: ممنوع `slate-200` / `teal-600` / hex صلب — كل لون من `--ws-*` أو كلاس `ws-*`.
2. **لا بطاقات KPI في الجسم** — الإحصائيات صف حقائق `ws-header__facts`.
3. أيقونات **lucide-react** فقط (لا bootstrap icons)، خطوط 11–13px.
4. البلوكات مدمجة (`ws-block`) بلا استدارة ولا ظلال؛ البلوك الأخير `--fill` يتمرر داخلياً.
5. طيّ الأعمدة الجانبية بمفتاح `ws:<اسم-الصفحة>:sidecol` في localStorage.
6. **المنطق لا يُمس**: الترحيل شكلي — نفس الـ hooks والـ handlers والسلوك، وأي إصلاح منطقي يكون commit منفصلاً.
7. CSS خاص بصفحة؟ فقط للضرورة القصوى وباسم `ws-<page>-*` داخل workspace.css (قسم مُعلَّم).
8. اختبار قبل الاعتماد: ديسكتوب + جوال (تراص الأعمدة) + ثيم داكن + `npx tsc --noEmit`.

## 6) الأداء (يُنفَّذ بالتوازي مع الدفعات)

| الإجراء | لماذا | متى |
|---|---|---|
| **تقسيم الراوتات** `React.lazy` لكل صفحة أدمن | الحزمة الحالية **6.4MB** — تحميل أول بطيء | مع المرحلة 1 (أكبر مكسب أداء في المشروع كله) |
| إبقاء `jspdf`/`html2canvas`/`xlsx` **dynamic import فقط** | تحذير البناء الحالي يشير لاستيرادات ساكنة تسحبها للحزمة الرئيسية | دفعة 2 و7 (صفحات الطباعة/التصدير) |
| `placeholderData: keepPreviousData` في استعلامات الفلاتر | الجدول لا يومض/يقفز عند تغيير فلتر — إحساس «برنامج» | أثناء ترحيل كل صفحة |
| `memo` لصف الجدول + virtualization (`@tanstack/react-virtual`) **فقط** للقوائم > 200 صف | الكثافة العالية = صفوف كثيرة في DOM | عند الحاجة (طلاب/كشوف) |
| ثبات مقاسات الأعمدة والصور | لا layout shift داخل مساحة عمل ثابتة | دائماً |

## 7) آلية العمل والاعتماد

```
دفعة → بناء → tsc + build → معاينة منك → تعديلات → اعتماد → commit → الدفعة التالية
```

- كل دفعة commit واحد مستقل برسالة `ui(ws): ترحيل <الدفعة> للنمط الملتصق`.
- العمل على branch الفرونت الحالي `fix/audit-2026-comprehensive` (لا main أبداً).
- أي صفحة لم تُرحَّل بعد تبقى شغالة بشكلها القديم — النظامان يتعايشان حتى نهاية الخطة.

«المنطق لا يُمس» بقيت قاعدةً للسلوك: نفس الـhooks والحمولات والمعالجات.
لكن **العرض الكاذب ليس منطقاً — هو عطب عرض**، وأُصلح في موضعه لأن تحويل شاشة
إلى النمط الملتصق مع إبقائها تكذب لا معنى له. الأنماط المتكرّرة:

1. **نِسَب بمقام خاطئ**: «١٠٠٪ توصيل» من الأجهزة لا الرؤوس · «٩٥ يوماً دراسياً»
   رقم مبذور · شريط تقدم الدليل بمقام ينمو بأيام الغياب.
2. **حقول تصل ولا تُعرض**: `end_date` (إجازة ٢٤ يوماً تظهر نقطة) · `is_working_day`
   (لا يُقرأ ولو مرة) · `blocks_messages`/`affects_attendance` · الأرقام الستة لبوابات الدليل.
3. **حقول تُصدَّق ولا تصل**: accessors بلا `$appends` → «✓ مكتمل» أخضر على كل صف.
4. **`isError` غير مفحوص**: فشل الشبكة يُصيَّر «لا توجد بيانات» — كذبة مطمئنة.

### توصيات للخادم (خارج نطاق الفرونت، لم تُنفَّذ)
- `AbsenceReferral`: إضافة `protected $appends = ['next_action_required','actions_progress','requires_protection_center']`
  — سطر واحد يجعل `absence-ladder.ts` قارئاً يتحقّق بدل حاسبٍ يوازي. (الفرونت لا يعتمد عليه ويبقى صحيحاً معه.)
- `absence_referrals.notes`: عمود واحد يُستبدل لا يُلحَق — كل إجراء يدهس ملاحظة سابقه.
- `/academic-calendar/weeks` و`/semesters`: لا يفلتران بالعام الدراسي. الخلل نائم ما دام
  عام واحد مبذوراً؛ لحظة بذر عام ثانٍ تنهار نسب «مِسطرة العام» لامتداد مجالها على عامين.
- `hijri_day` صيغته `MM/DD` لا يوماً — والعطب حيّ أيضاً في `getFullHijriDateAttribute()`.

### أعطاب خادمية حرجة صُحّحت (كلها مُتحقَّقة بالتنفيذ على القاعدة الحيّة)
1. **BelongsToSchool على ٧ موديلات نماذج بلا عمود school_id** — index/show/publish/destroy تموت
   بـ1054 عند أول نموذج. نائم فقط لأن الجداول فارغة. (لا تُضاف الأعمدة: المسار العام بلا
   EnsureSchoolIsActive فتُكتب الردود school_id=NULL وتختفي.)
2. **AcademicSemester::current() عالقة على راية is_current** — فصل انتهى قبل ٦ أشهر، وكل
   التوزيعات في الفصل الآخر ⇒ **كل معلم يفتح خطته بلا منهج**. صارت تحلّ بالتاريخ كالموديل الشقيق.
3. **قالب الاستيراد ↔ المحلّل** — القالب ٥ أعمدة والمحلّل ٦، فيسقط كل صف، ثم `whereNotIn(col,[])`
   = `where 1=1` ⇒ ١١٠٣ طالباً في «سيُحذفون». الحارس أُضيف للمعاينة والقالب طوبق.
4. **مقام تغطية الداشبورد** يعدّ المنسحبين + **المستأذنون** يُبخَّرون من المرصودين + **ختم الحساب**
   generated_at.
5. **إنذار الاشتراك** كان في الفرع غير-الملتصق وحده ⇒ **كل ١٩+ صفحة محوّلة فقدته**. رُفع للفرع الملتصق.
6. **رسائل الغياب**: parent_phone الميّت (guardian_phone غير موجود) · العدّ الكاذب (return true) ·
   سجن التخطّي (بلا فحص status) · N+1 · الترتيب.
7. **status المواد** يُرمى صامتاً · **سعة ورقة الباركود** (هدر ٥٦٪) · **تطبيع الوقت العربي** في
   التحضير (12:14 م تعبر الظهر) · **courses/prescribed** شُحنت في حمولات مدرستي والخطط.

### توصيات خادمية سُجّلت للمالك (لم تُنفَّذ — خارج التحويل البصري)
- **فارس**: `FarisSyncService:223-230` يصفّر مطابقات كل السنوات بلا قيد، والمطابقة تعيد سنة
